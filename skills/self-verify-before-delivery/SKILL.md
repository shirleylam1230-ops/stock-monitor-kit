# 交付前自迭代验证（Self-Verify Before Delivery）

## 核心原则

**完成 ≠ 构建工具说成功。完成 = 用户按他最新那条提示词去操作一遍，能得到他预期的结果。**

禁止仅凭以下信号向用户宣告"已完成/已上线/已修复"：
- 构建脚本输出无报错
- 发布接口返回成功
- 本地文件已生成
- 截图看起来"差不多"

以上任何一条都只是必要条件。必须实际模拟用户操作并逐项核对预期，才算验证完成。

## 触发时机

凡准备向用户回复"已完成、已发布、已更新、已修复、请查看"之前，且交付物属于以下任一类：
- 网页应用 / HTML 页面（本地或线上）
- 发布到线上的站点更新
- 报告、文档、数据文件
- 管道产出（日报、邮件摘要等定时任务结果）

不适用于：纯聊天回答、概念解释、无交付物的问答。

## 执行流程（五步，不可跳过）

### 第 1 步：提取验收标准

重读用户**最新一条**提示词，把用户的意图翻译成可客观核对的验收项。每项必须包含：**操作（用户会做什么）→ 预期（会看到什么）**。

示例转换：
- 用户说"把这个模块加到 App 里" → 打开页面 X，能看到模块且位置正确；旧功能不受影响
- 用户说"更新最新版本" → 线上 URL 的版本标记/生成时间是本次构建时间；新内容在页面上可见
- 用户说"修一下 XX 按钮点不动" → 实际点击该按钮，触发预期行为
- 用户说"数据错了" → 打开对应页面核对具体数值与数据源一致

### 第 2 步：组装验证清单

把验收项整理成清单，每项标注验证方法：
- `click`：浏览器实际点击（用 agent-browser 或 playwright-cli 技能）
- `read`：打开页面/文件读取具体内容
- `http`：curl 拉取线上 URL 并比对关键字段（版本时间戳、新增内容关键词）
- `data`：核对页面数值与源数据（数据库/JSON）一致

禁止用"应该没问题""逻辑上是对的"代替任何一项的实测。

### 第 3 步：模拟操作执行

按清单逐项执行，规则：
- **验证对象是最终形态**：涉及线上发布的，必须在**发布完成后**验证线上 URL，不得只验本地文件（CDN 缓存、发布失败、旧文件覆盖是高频失败点）
- **走用户的真实路径**：用户说了"点这里"，就真的去点；不要用 grep HTML 源码代替点击验证交互行为
- **改动波及的面都要查**：修改涉及多屏/多页面时，每一屏都要过一遍，不只验改动点
- **核对具体内容而非存在性**：验证"新增的条目在页面上"时，要确认条目内容完整、排序正确、没有被渲染截断

### 第 4 步：判定与自修复循环

- 清单项全部通过 → 进入第 5 步
- 任一项失败 → **当场修复 → 重新走第 3 步（对失败项及受影响项重验）**
- 修复-重验循环最多 3 轮。3 轮后仍未通过的：
  - 停止盲试，回到根因分析（读取源码/日志/对照数据源）
  - 若仍无法解决，如实告知用户：失败的具体现象、已尝试的方法、当前阻塞原因。**严禁带病交付并宣称完成**

### 第 5 步：交付与教训入库

- 全部通过后交付，回复中简要附上验证结论（验了哪些项、结果如何），让用户知道验证做过
- 若本轮发现了新的失败模式（尤其是交付后用户又报问题的），把教训追加到 `references/lessons.md`（格式见该文件头部说明），让下一次验证变聪明

## 高频失败模式速查（验证时重点盯防）

1. **只验本地、没验线上**：构建成功 ≠ 发布生效 ≠ CDN 刷新。线上站必须 curl 或打开线上 URL 确认版本时间戳
2. **渲染截断**：数据源有条目、页面只显示部分（硬编码条数上限、容器高度截断）——用页面实际渲染出的条目数与源数据条数比对
3. **存在性 ≠ 可用性**：元素在 HTML 里存在，但点击无响应、被遮挡、在视口外
4. **旧文件覆盖新文件**：多入口构建（index/archive 等）互相覆盖；验证每个入口文件的关键差异内容
5. **缓存陷阱**：页面内嵌版本号没更新、强缓存未失效——比对线上与本地文件的哈希或生成时间
6. **回归破坏**：新改动破坏旧功能。至少抽查一个未改动的相邻功能仍正常

## 无人值守场景（定时任务/自动化中调用）

流程不变，但因无法提问用户：
- 验收标准取自任务提示词中对产出的描述
- 3 轮修复失败后不中断任务（除非阻断后续步骤），在最终回复中**显著标注**未通过项与原因，不使用"已成功"字样
- 把失败详情写入任务记忆文件供下次参考

## 工具选择

- 浏览器操作（点击、截图、读渲染后文本）：优先 agent-browser 技能；轻量校验用 playwright-cli
- 线上内容校验：curl + 关键词/时间戳比对
- 静态 HTML 内容核对：可直接读文件，但**交互行为必须真实点击验证**
