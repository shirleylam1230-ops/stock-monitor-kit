# 教训库（Lessons）

本文件是自迭代验证的累积记忆：每次发现"交付后用户仍发现问题"或"验证中抓到的真实失败"，追加一条。
不删除旧条目；同类教训合并时保留最早的根因描述。

## 条目格式

```
### YYYY-MM-DD｜失败模式名称
- 现象：用户看到/遇到什么
- 根因：实际原因
- 教训：下次验证时增加什么检查项（可直接并入 SKILL.md 速查表）
```

---

### 2026-09-17｜数据源有条目但页面不显示（渲染截断）
- 现象：动态板块 JSON 里有 13 条数据，页面只渲染 8 条，新增的机构解读等条目静默丢失；用户在页面上"看不到更新"，导致反复要求重新更新
- 根因：构建脚本硬编码 `items[:8]` 只渲染前 8 条，补充数据后被排在末尾截掉；构建无任何报错，问题不暴露
- 教训：验证渲染完整性时，**比对"源数据条数"与"页面实际渲染条数"**，不能只确认"页面有更新"。（已修：放开条数上限）

### 2026-09-17｜发布成功但线上仍是旧版（CDN/缓存类）
- 现象：发布接口返回成功，但线上页面内容为旧版本，用户侧看到的一直没变
- 根因：CDN 缓存未刷新 / 未用线上实际返回内容验证
- 教训：任何发布动作后，必须 curl 线上 URL，比对**版本时间戳（如"生成于"）等于本次构建时间**，且本次改动的新增关键词在线上页面可检索到。此检查已写入日报/App 流程。

### 2026-09-17｜模拟操作时浏览器带出无关页面（会话残留）
- 现象：拉起浏览器做页面验证/抓取时，自动打开了抖音、微博等无关标签页，干扰判断且拖慢任务
- 根因：Chrome 启动参数带 `--restore-last-session`，配置目录会话文件残留历史标签页
- 教训：验证用浏览器必须干净启动（无会话恢复参数）；启动后先核对标签页列表再执行操作。
